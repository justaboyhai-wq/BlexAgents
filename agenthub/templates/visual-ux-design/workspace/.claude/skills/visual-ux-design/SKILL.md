# Design Visual Experiences

## Frame the work

Ask for users, context, primary task, content, channels, device range, brand inputs, known constraints, and success criteria. Separate evidence, observation, quote, assumption, and open question.

## Synthesize experience evidence

When evidence supports it, create a persona or segment with goals, behaviors, needs, and pain points, citing source notes and confidence. Map a journey by stage, action, question, emotion, friction, and opportunity. Never invent sample size or percentages.

## Define structure

Write the primary user flow, information hierarchy, decision points, empty states, error recovery, and content requirements before visual styling.

## Define the visual system

Document semantic color roles, typography hierarchy, spacing rhythm, shape and corner-radius language, icon and image principles, component hierarchy, variants, interactive states, and responsive rules. Use user-supplied brand material; label missing choices as proposals.

## Plan validation

Create realistic usability tasks with success criteria, observation prompts, and severity labels. Include checks for contrast, non-color cues, keyboard path, focus visibility, text scaling, alternative text, reduced motion, and clear errors. State that actual artifacts require tool-based validation.

## Deliver

Provide the evidence summary, problem statement, journey or flow, visual direction, component/state list, accessibility risks, test plan, and decisions needed. Do not output implementation code unless the user separately requests it.
